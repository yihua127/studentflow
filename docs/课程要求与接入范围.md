# Track 4：功能范围与账号接入

依据 Week 0 的 Capstone_Project_Spec_v5.pdf 和 Capstone_Project_Tracks_v4.pdf，2026-10-09 核对。

## 老师原文支持的范围

- Spec v5 第 1 页明确建议聚焦一个领域做深，举例包括 “deadline extraction from one mail platform done really well”。不应把列举的平台名称自动解释为每个平台都必须接通。
- Tracks v4 第 9 页明确写明 “Google Workspace APIs are the equivalent if you live on Gmail”。因此个人 Gmail 是 Track 4 允许的邮箱路线。
- 同页建议 “Start read-only”。先完成本人真实邮箱的只读访问符合推荐顺序。
- 第 9–10 页同时列出线程摘要、决策与行动项、会议议程和会后跟进；不能因选用 Gmail 就自动取消这些协作能力。

## 10 月 16 日的开发目标

本人授权一个真实邮箱 → 查看少量邮件列表 → 导入选中邮件与实际附件 → 提取或核对任务 → 人工确认 → 生成学习计划。

这是小组希望展示的早期成果。Spec v5 第 3 页将 Sprint 1 开发进展标为 optional，没有要求在这一天完成所有平台连接。

## 后续开发边界

1. 邮箱：分类、截止日期提取、回复草稿与发送前确认。
2. 日历：读取真实忙碌时段，再接经过用户确认的日历写入；公开版 A/B 场景是完全虚构的本地开发样例。
3. 跨来源材料：邮件、附件、课程材料与小组讨论内容的来源回溯、去重和日期核对。
4. 协作：线程摘要、行动项、议程与会后跟进。若使用用户导入的聊天内容，应标为“线程内容分析”，不能写成“Teams API 已接通”。在 Sprint 1 范围和风险页明确该输入方式，获取老师对最终范围的反馈。

## Teams 权限的具体限制

Microsoft Graph 的聊天读取接口支持工作／学校账号，**不支持个人 Microsoft 账号**，因此个人 Teams 也不适用这个接口。个人 Outlook 的邮件接口可用，并不表示个人 Teams 聊天接口同样可用。

NUS 账号的应用注册或用户同意受限制时，应取得学校对应用的授权，或由老师提供可用测试环境。不能通过更换客户端或借用其他应用身份绕过学校的审批。

微软依据：[Teams 聊天读取权限](https://learn.microsoft.com/en-us/graph/api/chat-list-messages?view=graph-rest-1.0)、[个人和组织邮箱邮件读取权限](https://learn.microsoft.com/en-us/graph/api/user-list-messages?view=graph-rest-1.0)。
